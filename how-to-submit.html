Detailed Diagnosis: Resolving "Predicted values must be in range [0, 1]"

What causes this error?
When participants first upload a model output to DrivenData, they frequently encounter the rejection message:
"Predicted values must be in range [0, 1]"

Even when all non-null values in the raster are between 0 and 1, this error fires if any pixel inside the valid scored footprint contains a NaN or non-finite value. In the GeoDAWN survey raster, the active valid footprint comprises exactly 5,167,373 pixels. In un-sanitized model outputs, missing data pixels inside this boundary cause the ingestion script's numeric assertion to fail.

How 8GEMSDOE guarantees compliance:
The 8GEMSDOE pipeline implements a strict conformance filter (src/submission_io.py):

  • Every pixel inside the 5,167,373 footprint is verified finite and bounded in [0.0, 1.0].
  • Every pixel outside the footprint is set to NaN with the geotiff tag GDAL_NODATA=nan.
  • The file passes all 13 independent automated gates before it is published.
