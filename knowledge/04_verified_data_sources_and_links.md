### Flagged Irregularities for Human Audit:
1. **GDR Link 1391**: The URL `https://gdr.openei.org/submissions/1391` currently returns "No submission found". GeoDAWN holdings are located directly via USGS ScienceBase and GDR search.
2. **DEM Links Format**: The official DEM file `1m_DEM_links.csv` on DrivenData is distributed as a text table, while the mirrored document `Digital-elevation-model-links-JSON.pdf` contains OCR-extracted JSON text.
3. **Sample Submission Values**: DrivenData's `sample_submission.tif` is identical to the known catalogue labels (60,988 positive pixels — re-verified 2026-09-26) rather than all zeros, providing a built-in format and dimension template. Contradicts the problem text's "predicts total fault absence"; the validator's footprint logic works under either reading.
4. **Missing magnetic-source-depth band**: the problem description lists a "top-of-crustal magnetic source depth estimate" band, but `training_features.tif` has none (19 tags verified); H5 was redefined to `ieq_n100a15 ∩ shallow basement` (`tests/test_bandlayout.py` fails loudly if a future revision adds one).
5. **SGMC per-state schema unverified**: `mrdata.usgs.gov/geology/state/about.php` would not fetch and `services.arcgis.com` TLS-fails in this sandbox, so shapefile/layer/attribute names are NOT asserted anywhere; the committed proxy raster must be rebuilt from official bytes on an unrestricted machine and byte-compared.
6. **Forum 11516 posts 3–4 unrendered**: the near-fault scoring ruling is UNVERIFIED — staff *intent* (11536) is verified, scoring *mechanics* are not. Never assert a near-fault credit rule.
