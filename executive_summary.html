Executive summary

What the competition asks for, how this repo answers it, and exactly how a submission gets uploaded. Read this page and you can submit.

Submit in 3 steps

  1. Take the file. The current candidate is the prebuilt apex submission downloads/submission.tif (sha b83ea0e70748…, 13/13 gates PASS, unique vs all eleven sibling artifacts — Results). Rebuilding from scratch: python scripts/train_apex_model.py, then python scripts/build_submission.py --strategy <name> --out submissions/ (unique timestamped name + paste-ready Note). The Note is what tells your submissions apart later — the file name is the submission name, the Note is the comment (submission form). The apex paste-ready note is logged in reports/submissions_log.json.
  2. Open the submissions page (signed in): DrivenData → GEMS → Submissions, click New submission / File to submit, choose the .tif (or a .zip containing it — a single-member ZIP is accepted).
  3. Paste the Note into the comment box and submit. Write the score down in reports/submissions_log.json next to the payload hash. Done.
Weekly discipline: 3 submissions per week, and exactly one final submission scored across both prize rounds, chosen without knowing private-test scores (rules §3.4, §3.5, §3.6.2). This repo spends at most one slot per week, only on the current holdout winner. Slot-spending log: Results.

The task in 60 seconds

Predict per-pixel fault probability across the GeoDAWN region (northwestern Nevada + adjacent eastern California) on a 100 m grid in EPSG:32611 (problem description). Features: GeoDAWN magnetics/radiometrics plus conductivity, detrended elevation, strain-rate, gravity, earthquake-density bands (training_features.tif), with 1 m DEM tiles via a links CSV. Labels for training: the USGS Quaternary / INGENIOUS catalogue (INGENIOUS compilation, DOI 10.15121/1881483). Labels for scoring: privately withheld new faults mapped by NLR/USGS experts — then, for the $250k Final Round, an expanded set the experts build after reviewing every team's predictions. Total prize pool: $300,000 ($50k Initial split 5 ways; $100k/$70k/$40k/$25k/$15k Final), deadline Dec 3, 2026 (competition home).

Our strategy (one line each)

  1. Apex near-catalogue submission (b83ea0e7…, built & valid): structural envelope + along-strike extensions + GBT anomalies — the untested near-catalogue bet. First-slot candidate.
  2. H1 — gravity edges for buried faults: TDR zero-contour + HGM on isostatic gravity. Measured 0.038/0.018 — falsified as a catalogue detector, untested for buried faults. Contrast candidate.
  3. H9 — valley-axis coherence: best measured arm (proxy 0.1416, catalogue 0.0753; still below random 0.171). First far-field contrast candidate. H3 (proxy 0.127) is the fallback.
  4. H2/H4/H5/H6: measured below random on both populations; no slots. H5 redefined (no mag-depth band in file).

Data placement (resolved 2026-09-26)

The DrivenData data tab requires login and Dropbox TLS fails in sandboxes, so training_features.tif, labels and the template were reassembled from the public sibling bridge and hash-checked against the pins in scripts/download_competition_data.sh (all match). On any machine with a browser session, prefer the authenticated files:

bash scripts/download_competition_data.sh   # prints the exact file→path map
# place the downloads into data/, then:
python scripts/prepare_data.py              # verifies + writes data/manifest.json

Then python scripts/holdout_validate.py (fixture) and python scripts/holdout_real.py (real bands) reproduce the validation tables. GPU is needed only for training scale-up; everything verified here runs on CPU.
