⬇ The file to submit

STATUS: builder ready · payload pending holdout winner

The DrivenData File to submit dialog asks for a single-band GeoTIFF (.tif) — or a .zip containing one — matching the submission format's CRS, shape and geotransform: EPSG:32611 · 100 m · float32 in [0, 1], NaN outside the footprint (official format). This repo builds that file with scripts/build_submission.py: unique name (gems8-<strategy>-<UTC>-<sha8>.tif), paste-ready Note, 13-gate validation as a hard gate, and a duplicate-payload guard.

No submission file is published yet — by design. The standing rule (see Hypotheses) is: no weekly slot is spent on an idea that hasn't beaten the current holdout best, and the holdout best on real bands does not exist until data/ is populated. The builder, validator and holdout harness are all verified working on synthetic fixtures in CI.

  1. Validate: python scripts/holdout_validate.py --report reports/holdout_top1.json
  2. Build: python scripts/build_submission.py --strategy topk_hard@0.03 --out submissions/
  3. Upload: file + Note into DrivenData → Submissions (full click path in How to submit).
If the platform answers Predicted values must be in range [0, 1]: a pixel inside the scored footprint was NaN (or outside [0, 1]). Our builder makes this structurally impossible — finite inside, NaN outside, clipped, then 13-gate checked. Details in How to submit § rejection.

What is scored (the asymmetry that shapes everything)

Training labels = the existing USGS/INGENIOUS catalogue. Scoring labels = a privately withheld set of newly expert-labelled faults in both prize rounds (rules PDF §1.1; competition structure). Known faults are masked/excluded from scoring — predictions there neither help nor hurt (forum 11516, organizer reply). Reproducing the catalogue is therefore not the goal; finding the unmapped faults is.

The metric in one paragraph

Distance-weighted Tversky index, α=0.2 (false positives), β=0.8 (false negatives), 300 m triangular kernel (R=3 px): each truth pixel is credited from its single best prediction inside the kernel; every predicted pixel far from truth pays 0.2. Official formulas + worked example (TP=3.00, FP=1.89, FN=2.00 ⇒ DTI=0.60): problem description. Our implementation: src/gems/metric.py, tested against hand-computed micro-grids in tests/test_metric.py.
